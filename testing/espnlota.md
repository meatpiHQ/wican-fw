**The ESPNetLink dongle updated through the WiCAN PRO** (prints `ESPNL OTA PASS`, ~45 checks, ~12 min, 1 planned WiCAN restart, the dongle restarts 3 to 5 times; 2026-10-19, `internal/TASK_fw_update.md` sections 6 and 9.3). The claim: the WiCAN reads the dongle's own release list (`<base_url>espnetlink/firmware/manifest.json`) with its channel, offers what the channel allows, stages the image in PSRAM, verifies it (size, sha256, an ESP32-S3 application image whose project name is `espnetlink-fw`, the version the list names), pushes it into the dongle's upload route over the USB link, waits for the dongle's restart and reads the new version back; a wrong image or digest never reaches the dongle; the WiCAN never restarts for it. rpi001 serves both lists and the images (`actors/fw_server.py` as the unit `fw_bench` on 8446); the images are the dongle build named by `--dongle-image` (default: the newest `espnetlink-fw_*.bin` in the dongle repo's `build/`) and copies with a patched version (`lib/fw_image.py`: N1 1.22.1-alfa.1, N0 1.22.0-beta.1), plus the WiCAN's own image for the wrong-product leg. Legs: o0 preflight + setup (the DUT on this build, a dongle reachable over USB with api >= 7, the bench CA as cert set `fwbench`, the settings staged with one restart, the lists published); o1 the row (present, reachable, the installed version, N1 offered with its summary, the notes proxied for `target=dongle`); o2 the install over USB (202, the job through checking / downloading / verifying / pushing / rebooting / pending_verify / verified with METRIC `o2_push_s` and `o2_total_s`, the dongle reports N1, `last_result verified`, the WiCAN's boot_count unchanged, the link back in `ncm_up`, the row up to date, a second install = `already`); o3 the explicit downgrade to N0; o4 a wrong sha256 in the list = `failed sha256_mismatch`, nothing pushed; o5 the WiCAN image listed for the dongle = `failed wrong_product`, nothing pushed; o6 `max_stage_bytes` 65536 = 409 `no_memory` before any byte; o7 (`--unplug`) `usb vbus 0` over /ws/cli at 25 % of the push = `push_failed`, the dongle back on its old firmware, the install again verified; o8 the original dongle image back under its own version string. Close: the settings as found, the cert set deleted, the server stopped, no unexpected WiCAN reset, no E line of the own tags, the fw_update task's headroom, the heap floor, 0 faults. Not covered yet (the dongle firmware's side, TASK section 6.6): the dongle refusing a foreign image or a wrong `?sha256=` itself, the wifi_modem transport, the dongle's own self-update, the crash rollback on the dongle.
