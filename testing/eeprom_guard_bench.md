# OBD chip EEPROM guard

Command: `python tools/testbench/obd/eeprom_guard_bench.py <dut_ip> [--port 35000]` (ON rpi001)

Needs: main fw on DUT + rpi001 + the ELM bridge

Moved from the `TESTING.md` test-kinds table on 2026-10-31 (the row's detail cell, whole, as paragraphs). The index row and the other stages: [../TESTING.md](../TESTING.md).

**OBD chip EEPROM guard** (prints `EEPROM GUARD PASS`, ~10 s): talks to the MIC like an ELM app over the TCP bridge and proves the driver guard (`obd_chip_guard.h`): `ATSP6` is rewritten to `ATTP6` (chip answers OK, `/api/obd_chip` `eeprom_guard.rewrites` +1), `ATPP 0C SV 23` (UART re-baud) and `STWBR` are refused with the ELM `?` (`.blocked` +1, the chip never saw them), `ATPPS` (summary read) passes, the chip still answers after. Needs the TCP ELM bridge (`obd0`/`br_tcp_obd`, canonical bench). Bench 2026-09-16: PASS. 2026-11-01 20:10, on the OBD chip protocol store fix build (`testing/attpstore.md`): PASS (6 checks; `rewrites` 0 to 1, `blocked` 0 to 2, `memory_off` stayed at 1: the bridge path gets no `ATM0`, by design). Trap: the bench DUT's `obd0` (TCP 35000) is bridged to `ws_can` as `br_echo` since the connections work of 2026-10-29, so the bench cannot reach the chip as the rows stand; for the run `br_echo`'s `a` side was re-pointed from `ws_can` to `obd` (a settings submit, planned restart) and put back after (a second), with the restore in a trap so it runs whatever the bench does. 21:47 the same evening, on the image with the app's reset intercepted (`ATZ` as `ATWS` + a hidden `ATM0`), in the ELM app bench's window: PASS (6 checks; `rewrites` 2 to 3, `blocked` 0 to 2, `memory_off` unchanged at 7 across the app's `ATSP6`). Trap found at 21:58: the bench needs AutoPID OFF or yielded. Its `drain()` reads until a 0.3 s gap, and with AutoPID polling at 14 requests a second the fan-out keeps the TCP client fed with the poll traffic (every subscriber gets every byte) before the bench has written anything that would make AutoPID yield, so the loop never ends (the 21:47 run passed only because a gap happened to fall). Run it on a DUT with AutoPID off, or after an app session has made AutoPID yield.
