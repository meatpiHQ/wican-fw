# The partition table rewrite, measured

Command: `python tools/testbench/system/partition_migrate_bench.py [--legacy-table <partition-table.bin of the v4.51p release>] [--dut 10.42.1.194]`

Needs: DUT console + PSU + rpi001 (the lease)

Moved from the `TESTING.md` test-kinds table on 2026-10-31 (the row's detail cell, whole, as paragraphs). The index row and the other stages: [../TESTING.md](../TESTING.md).

**The partition table rewrite, measured** (prints `PARTITION MIGRATE PASS`, 15 checks, ~2 min, two PSU cycles; 2026-10-10, the fix for the row above: component `partition_migrate`, run by `main_boot_layout()` right after `restart_tracker_init()` and before any data partition mounts). Clears the DUT's latched faults, writes the v4.51p release's partition table at 0x8000 over a running v6 (same app slots, so the same image boots; the filesystems stay where they are), PSU cold boot with the console: `W partition_migrate: the partition table in flash is another firmware's layout (storage 6144 KB at 0x9EE000 -> settings 256 KB at 0x9EE000, storage 5888 KB at 0xA2E000): rewriting it with this build's (one 4 KB erase, one write, then a restart)`, `I partition_migrate: partition table rewritten in N ms (erase N ms, write N ms): restarting into the new layout`, then `restart_tracker: boot #2 (history kept): reset=software planned=partition_migrate/boot` in the same capture, no superblock probe line (nothing formatted: the swap alone is lossless), 0 E lines, `WICAN HEALTH errors=0`, the DUT back on its bench lease with its own settings, `/api/restart/history` latest record `partition_migrate` / `boot`; a second PSU cold boot: no partition_migrate line, 0 E lines, `WICAN FLASH writes=0 erases=0`.

**2026-10-10: PASS, `rewritten in 22 ms (erase 19 ms, write 3 ms)`** (`test-reports/logs/partition_migrate_20261010_0344`): the window without a valid table is those 22 ms. Host side: `.\test.ps1 host partition_migrate` = 12 Unity tests on the pure rule with the two real tables as byte vectors (same, migrate, a moved app slot, a changed nvs/otadata, a missing phy_init, blank, garbage, an extra data partition, the MD5 terminator, too many entries, an unparsable own table): 12/12 PASS 2026-10-10 (and restart_tracker 46/46 with the new `partition_migrate` reason and `boot` source). Needs `MEATPI_COMPONENTS_PATH` set when launching test.ps1 from a bare shell, else the host sync ships the stale `components/meatpi` clone (restart_tracker showed 8 tests instead of 46)
