# A device that crashed says where, still says it after a power cut, and stops crashing after the third time

Command: `.\test.ps1 crashnote`

Needs: DUT console + PSU + `ssh rpi001`

Moved from the `TESTING.md` test-kinds table on 2026-10-31 (the row's detail cell, whole, as paragraphs). The index row and the other stages: [../TESTING.md](../TESTING.md).

**A device that crashed says where, still says it after a power cut, and stops crashing after the third time** (`TASK_crash_note.md`, `TASK_crash_loop_brake.md`; two stages, ~7 min, each ends with a PSU power cycle and leaves the DUT as found; both hold the DUT's console and type there).

**Stage 1, the crash note and the stored crash report** (`tools/testbench/system/crash_note_bench.py` → `CRASH NOTE PASS`, 81 checks, ~100 s, 4 crashes on purpose + 1 planned restart): `restart_tracker --panic`, `--panic=fault` twice, `--panic=wdt` (the three reset classes the tracker tells apart: `abort()`, an invalid store, the interrupt watchdog). For each, the NEXT boot's record in `/api/restart/history` must carry the note: the reset reason, the kind, IDF's reason or the abort text, the fault address, the task (`cli_console`: a typed command runs on the console's task), the uptime (against `/api/status` just before), the image id; its backtrace must be the frames the console's `Backtrace:` line delivered whole (at 2 Mbaud that line can break off: the note may hold more, never different ones), and decoded with the build's ELF it must name the function that crashed (`cmd_restart_tracker`, `panic_fault`, `panic_wdt`).

**Flash**: a crash that is news is stored in NVS by the boot that files it, and the boot's own `WICAN FLASH` line must show that one small write (measured 9 to 12 writes, 468 to 500 bytes, 0 erases) and name it once (`crash report stored`); the SAME crash again (the second `--panic=fault`) must leave `WICAN FLASH writes=0 wbytes=0 erases=0 ebytes=0`; so must a planned restart. The stored report must be that crash (`report` in the history; `GET /api/restart/report` with its `Device:`, `Firmware:`, `Image:`, `Backtrace:` lines). Also: `c0` the PC's ELF is the DUT's firmware by image id (a mismatch stops the run and says so), one `previous run crashed` log line per crash and none after a planned restart, the notes still there after a later planned restart, `tools/crash_decode.py` decodes the notes, the stored report, and the report TEXT on its own (`--report`: what a user would send), the console prints the same report (`restart_tracker --report`) with NVS's occupancy (118 of 504 entries used on the bench unit), no E line of the tracker. Every run that follows a crash is marked settled (`restart_tracker --settle`), so the four crashes are four first crashes and the brake stays out of this stage. `c8` power-cycles the DUT through the PSU: counters 0, no note out of power-on memory, and **the stored report still there, byte for byte, read back with `writes=0`**; `c9` clears it (`DELETE /api/restart/report`), settings untouched, no fault. `--no-power-cycle` on the script keeps notes and report for a look by hand.

**Stage 2, the crash-loop brake and the crash park** (`crash_park_bench.py` → `CRASH PARK PASS`, 39 checks, ~5 min, 4 crashes + a forced sleep + a PSU power cycle): `p0` the two references: the supply current awake and in the firmware's own sleep mode (`sleep test 30`), and the LED chip breathing red on request, read back from its registers (`led -d`: `PATST=0x01`, `LCFG0=0x13`, `L0T0=0x61`, `L0T1=0x68`; the one part of a park no instrument on this rig can see); `p1` two quick `--panic=fault` with no settle in between: the DUT boots, the streak reads 1, then 2; `p2` the third: **parked** (console `WICAN PARK streak=3 parks=1 retry_s=40 bare=0`, no LED or OBD chip complaint, HTTP silent, supply current within 8 mA of sleep mode and under half of awake: measured 46 to 47 mA parked, 43 to 44 mA sleep mode, 158 to 164 mA awake); `p3` the bench's one-shot knob (`restart_tracker --park-retry 40`) ends the park after 41 s: one normal start, `park_retry` / `park` in the history, the record before it `mode: park`, the streak still 3, the stored report says `Loop: 3 crashes in a row; the device parked itself`, the whole loop cost exactly two flash writes (budget 4 → 2), and the awake current is back (USB rail, OBD chip); `p4` that start crashes too: parked AT ONCE (`streak=4 parks=2 retry_s=0`), and with no timer it stays parked (50 s watched) and writes nothing; `p5` a PSU power cycle is a fresh start: boot 1, the count empty, the report still there; `p6` as found.

**Not in here, because it needs a hand on the device**: the button on a parked DUT (hold until sky blue = one start; keep holding until yellow = safe mode) and safe mode's crash report page; `TASK_crash_loop_brake.md` section 7 has the three-minute check by hand. A failed stage 2 power-cycles the DUT itself rather than leave it parked

**2026-10-31 (the HTTP server task on a PSRAM stack): `CRASH NOTE PASS` and `CRASH PARK PASS` on the fourth run** (the first died on an unresolved PSU port, the second too after the preflight's refresh dropped the pin, the third on an NVS page compaction under the `wdt` store). The stored report's NVS reads and writes run through `flash_jobs_run()` now (in line on the boot task). Two rig lessons: two FTDI ports on the PC (COM50, COM407) leave the PSU role ambiguous until `python tools/testbench/detect_ports.py --probe-psu` pins it, and `detect_ports.py` keeps a confirmed pin across the preflight's refresh since that night; and NVS compacts a full page under a store now and then (135 writes, 2680 B, one 4 KB erase, the same signature on the `fault` leg of one run and the `wdt` leg of the next, every other store 9 to 12 writes): `crash_note_bench.py` accepts one compaction per store (the erase present, the writes within a page's worth, metric `<name>_store_compacted`). Floors: crash note 51,708 B, crash park 42,064 B. Report `2026-10-31_2154_crashnote.md`.
