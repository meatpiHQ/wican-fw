# A car without a readable VIN can be forgotten, renamed and given a profile from the web UI

Command: `python tools/testbench/obd/autopid_fp_forget_bench.py [--dut localhost:18081]` (PC, the DUT through an ssh tunnel, the simulator through sim_net)

Needs: PC + the ECU simulator (its default profile active, VIN `1WCAN0FW0P0000001`, its car in the vehicle store or learned by the bench); the DUT on the bench AP, the PSU above the sleep voltage; 2026-10-28: a precondition for a folded face on the VIN car: the new-car bench's fold-in had left the fixture car's fingerprint as a face and the detection then recognised it instead of forking (1 car, no fp: entry); PASS again that evening once the face was cleared (46 checks with the precondition)

Moved from the `TESTING.md` test-kinds table on 2026-10-31 (the row's detail cell, whole, as paragraphs). The index row and the other stages: [../TESTING.md](../TESTING.md).

**A car without a readable VIN can be forgotten, renamed and given a profile from the web UI** (prints `AUTOPID FP FORGET PASS`, 45 checks, ~2.5 min, no restart; discussion #1018, 2026-10-25: a 2021 Toyota Sienna on a 6.0.0 beta showed a second car, "Car 0a70" with "no VIN, ECU set 0a70ff20, 15 std PIDs, Profile pending", beside the Sienna's VIN entry, and Forget on it did nothing). Such a car is keyed `fp:<8 hex>`; the browser sends the key through `encodeURIComponent` (`fp%3A...`) and the device did not decode it: every per-key route answered 404 `no such route`, so the Forget button toasted "no such route" and the car stayed, and a profile could not be set on it (it stayed Profile pending); a VIN key has nothing to encode. The bench plays the duplicate on the ECU simulator (its default profile with seven standard PIDs disabled, the fixture `fixtures/ecu_sim_fp_dup_profile.json`, so the main ECU's support bitmap differs and the adoption rule keeps the entries apart; the VIN replies 0902 and 22F190 silenced through the simulator's error injection), runs the detection (a second car `fp:<hash>`, no VIN, current, Profile pending, "Car <4 hex>", fewer standard PIDs), then the routes with the key percent-encoded (PUT renames, POST activate answers ok, DELETE forgets: the list is back to one car), the raw-colon form (a second detection, DELETE with the colon), the refusals (a torn escape and a non-hex escape 404 `no such route`, a forgotten car's decoded key 404 `no such vehicle`, a VIN key unchanged) and, right after the current car is forgotten, the no-car prelude on the test route's transcript (`ATH0`, `ATTP0`, no empty command). Restores the simulator (errors cleared, the default profile reloaded, the fixture deleted), detects the VIN car again (current, the store as found) and compares the tables with the save.

**Reproduced before the fix (2026-10-26, beta.4 on the bench, the real page through Playwright):** `DELETE /api/autopid/vehicles/fp%3Abe34221b` 404, toast "no such route", the car stayed; the same press after the fix: 204, "Forgotten", one car. Found with it: the chip prelude sent with no current car (and the K-line / J1850 preludes) carried an EMPTY command where its `ATH0` was (the chain sender's print strip of issue #1014, meant for the user's inits; the chip answered `?`): fixed in the sender, the transcript check covers it
