# Builds + flashes that component's self-contained on-target app (components/<comp>/test_apps), captures serial,...

Command: `.\test.ps1 target <component>`

Needs: DUT console port (the preflight picks it; + rpi001 for ble_manager)

Moved from the `TESTING.md` test-kinds table on 2026-10-31 (the row's detail cell, whole, as paragraphs). The index row and the other stages: [../TESTING.md](../TESTING.md).

Builds + flashes that component's **self-contained on-target app** (`components/<comp>/test_apps`), captures serial, verifies `TEST DONE` with no crash signatures. `ble_manager` is special: waits for `BLE READY`, then drives the DUT from rpi001's BLE controller (`ble_bench.py`) and passes on `BLE BENCH PASS`. `restart_tracker` is special too (2026-10-05): its app crashes the DUT on purpose, one step per boot (15 steps, about a minute), and `tools/testbench/system/rt_target_check.py` judges every crash note against IDF's own panic text of the same crash (`RT TARGET PASS`, 85 checks since the evening of 2026-10-05: the same 13 crashes, all quick and all different, also prove the crash-loop brake and the stored crash report on the device's own RTC memory and NVS: the streak counts every one, the verdict turns to `park` at the third, the report is stored four times and not a fifth, and the app clears it at the end); run it at every IDF version bump. Since the components live in their own repository a test app's `..\..\..\sdkconfig.defaults` and partition table do not exist there: `test.ps1` stages copies from this repo for the build and removes them (no target app had been built since the split until 2026-10-05; the other apps still build every component of the tree, `restart_tracker`'s and `filesystem`'s use `MINIMAL_BUILD`). `filesystem`'s app carries the 32 GB card of issue #982 since 2026-10-11 (`INFO_SD`: a link-time wrap of `esp_vfs_fat_info` stands in for the card, 1,897,503 clusters of 16 KiB, one used; a failed check withholds `TEST DONE`, so the stage goes red): before the fix it printed `total=1023918080 ... ok=0` and `TEST FAILED checks=1` on the bench unit (`test-reports/2026-10-11_2005_target_filesystem.md`); with `filesystem_info()` in `uint64_t` the same day: `ok=1`, `TEST DONE`, 0 E lines, `RESULT: PASS` in 16.4 s (`2026-10-11_2028_target_filesystem.md`). The bench unit's own card is the field-faithful check: a 16 GB SanDisk SC16G that `/api/fs/info?path=/sd` reported as 3,038,806,016 B (2.83 GB on the File Manager) for three months and reads as 15,923,707,904 B (14.83 GB) since, equal to `/api/backup/status` `free_bytes` + used; `test-reports/logs/issue982_20261011/files_page_real.mjs` reads the page in Chrome through a tunnel and prints AGREES / DISAGREES against that sum.

**Flash the main firmware back afterwards** (`.\build.ps1 -Flash COMx`)
