**Log timestamps that survive the clock's history** (prints `LOG CLOCK PASS`, ~10 min, 3 planned restarts + 1 PSU power cycle; issue #984, `internal/TASK_log_clock.md`, `data_logger/README.md` "Time"). The claim: every row is stamped in UTC epoch ms, a row queued before the clock was set or stepped is written with the corrected stamp, the files rotate when the clock becomes valid or moves by a minute or more, the device writes down what its clock did (`/sd/logs/clock.jsonl` + in-band markers), the relative formats never run backwards, and a file written before a step can be re-based from the device's own record. The instrument is `tools/testbench/actors/sntp_server.py` on rpi001 (a 48-byte SNTP responder on UDP 123 as a transient root unit `sntp_bench`; its offset is a number of seconds in `/tmp/sntp_offset`, re-read per request), the DUT's `rtc_manager.ntp_server` points at the Pi for the run; the console commands go over the ws_cli bridge on the tunnel; the OWON on this PC cycles the DUT for the unsynced boot. Legs: `L0` preflight (the clock surfaces, the card, the settings staged: params jsonl + CAN mf4, one restart; the journal has this boot's line); `L1` a sync through the real path (the step measured against the Pi's clock, journaled with the two open files, rotated iff a minute or more); `L2` a forward step of +1 h through SNTP: rows drained before the step stay in the old file which ends with the marker and the new file is named by the corrected clock, then rows QUEUED before a second +1 h step and written after it carry corrected stamps (the writer's re-base, the gate held across the step), the export emits no marker as a point; `L3` a backward step of -2 h through `POST /api/rtc` with mf4 frames: the old mf4 parses with monotonic non-negative times and a header start the corrected clock agrees with, the new file is named `newest + 1`; `L4` the field case: `rtc --forget`, the actor down, a PSU power cycle: the boot has no clock (`valid false`, one W line, no E line), its rows at 1970 + uptime in a file of its own (`newest + 1`, never resumed into a synced file), the actor up and a sync: the journal's `valid` line (56 years, the files), the rotation into a file named now, the chip rewritten (`rtc -r`), the `.wdl` ends with the 0x04 marker; `L5` the tools: `wdl_dump.py --strict` prints the marker, `log_clock.py --rebase` lands the unsynced rows in the 15 min before the sync and the L2a rows at their corrected time, `--show` prints the table; `L6` restore (settings as found, the actor stopped, a last sync at +0 so the DUT keeps the Pi's clock), no unexpected reset since the power cycle, no E line of `data_logger` / `rtc_manager`, the writer's stack headroom, the heap floor.
