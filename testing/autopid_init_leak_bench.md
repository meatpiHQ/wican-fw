**A custom row's init does not leak into the standard rows** (prints `AUTOPID INIT LEAK PASS`, 22 checks, ~2 min, up to two planned restarts; issue #964, 2026-10-20: a 2018 BMW 640i GT's custom UDS odometer row (`ATSH6F1;ATCEA60;ATCRA660;ATFCSH6F1;ATFCSD60300000;ATFCSM1`) left the chip on the gateway behind extended addressing, every Mode 01 row that followed went there, the gateway answered `7F 01 11` and the values froze). The vehicle is the ECU simulator (7DF/7E8) plus `actors/pcan_ext_addr_ecu.py` on the PCAN (the extended-addressed ECU on 0x6F1 + address 0x60, answering on 0x660: `62 D1 07` for the odometer, `7F 01 11` for service 01; it also witnesses every 7DF / 7E0-7E7 request and rewrites a JSON summary every second). Legs: the report's table is PUT (nine standard rows the simulator answers + the ODOMETER custom row, one group every 5 s) and autopid switched on (submit-reboot when it was off); four cycles watched on `/api/autopid`: every standard value keeps moving after the custom row (its `ts_us` advances every cycle), the odometer reads 123456, `polls_failed` does not grow, NO service-01 request reaches the extended address while 7DF carries them; then test-a-PID of the custom row followed by a standard one: the transcript carries the restoring prelude (`ATSH7DF`, `ATCRA`, `ATCEA`, `ATFCSM0`) and the answer is `41 0C` (RPM 800); tables and settings restored.
