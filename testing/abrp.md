**ABRP against the real Iternio API** (prints `ABRP LIVE PASS`, or `ABRP LIVE PARTIAL PASS` without a user token; ~5 min, 2 planned restarts; 2026-10-13). The mock leg of the data destinations bench proves the request shape; this one proves the service accepts it. Legs: `L0` the api_key against `get_carmodels_list` from the PC (and `--car-model` against the list); `L1` host routes on the Pi to Iternio's addresses for the run (the bench subnet has no internet path by itself: `ip route replace <ip>/32 via 192.168.8.1 dev eth0`, refreshed every 20 s while the run lasts, removed at the end; `--no-routes` when the DUT has its own internet), the DUT's clock within 120 s of the PC (ABRP's `utc` is the point's time), the originals saved; `L2` three rows every 5 s beside the originals (`abrp` = the key as a query parameter, `abrph` = `Authorization: APIKEY`, `abrpx` = a wrong key staged at 2 s: the 5 s floor applies), one planned restart, secrets never returned, `/api/destinations/abrp` naming the fields the car lacks (`soc` from `SOC`, `power` from `HV_W`); `L3` the counters over the window (full mode: accepted at the row's cadence, every 5 s within 2 s, 0 fail, HTTP 200, the device-wide pacer's `waits` > 0; negative mode: HTTP 401 `abrp: error "Unauthorized Token"` on both valid-key rows; always: the wrong key refused `"Unauthorized Key"` and backing off, fewer attempts than laps); `L4` the Test button on each row, back to back (the pacer holds Tests as it holds rows) + a 404 for an unknown name; `L5` Iternio's `get_telemetry` knows the token's vehicle (its latest point and `is_connected` are reported, not judged: Iternio's pipeline runs minutes behind and keeps no new point for an unmoved car); `L6` the originals restored, no unexpected reset, no own E line, the poster's (`data_dest`) stack headroom, the heap floor, the IDF client's E lines counted. Credentials: `internal/abrp_credentials.json` (gitignored; `api_key` + `user_token`, the token from the ABRP app's live data setup for the vehicle, Generic); the bench prints neither, the DUT returns neither (`has_token` / `has_api_key`), and get_telemetry's position values are withheld. Without the token the refusal path still proves DNS, TLS through the built-in bundle, both key transports and the verdict text (before 2026-10-13 the firmware showed a bare `abrp: error`: Iternio's `errortext` was not read). Iternio allows 2 requests per second per key; two valid rows every 5 s plus three Test deliveries stay far below it.
