# WiCAN PRO 6.0.0-beta.2

Supported device: [WiCAN PRO](https://www.crowdsupply.com/meatpi-electronics/wican-pro) only. Home Assistant: v6 requires the [meatpi-multi-device](https://github.com/meatpiHQ/ha-wican/tree/meatpi-multi-device) branch of the ha-wican integration.

## Before you update

<!-- /release.py:layout -->
- Coming from beta.1 with the Home Assistant integration: if the device parked itself (LED breathing red), take this update from safe mode: hold the button until the LED turns sky blue, keep holding until it is yellow, join the device's own access point (its name starts with `WiCAN_`, password `@meatpi#`), open `http://192.168.0.10` and upload the firmware there. Your settings are kept.
- Coming from a v6 alfa or beta: settings, profiles and files are kept.
- Coming from firmware 4.x: the stored files, logs and the saved configuration are erased by the new partition layout; download a backup first (System > Maintenance > Configuration backup), the device restarts once more on its first start.
- In case of a boot loop, perform a [factory reset](https://meatpihq.github.io/wican-fw/factory-reset/factory-reset).

## Bug fixes since beta.1
- Fixed a crash on every Home Assistant webhook push: a beta.1 device with the Home Assistant integration registered crashed about 15 s after each start, three times, then parked with the LED breathing red. The firmware update status read the flash from the webhook task; it reads a record taken at boot now.
- A firmware update no longer freezes the device for about 5 s at its start: the whole image area was erased in one go before the first byte arrived, long enough for the task watchdog to log an error. The flash is erased as the image arrives now.
- An OBD app over the WebSocket channel could connect at the wrong moment and receive nothing (the device had just dropped it as a dead client while its handshake was still in flight, and let a third client in). The handshake moment is recognised now.

## New since alfa-06
- Firmware updates from the MeatPi release list: System > Firmware update shows what the selected channel (stable, beta or alfa) offers, with the release notes, and installs it from the device. A new image that crashes three times is rolled back on its own.
- A connected ESPNetLink is updated through the WiCAN PRO, over USB or WiFi, from the same card (dongle firmware 1.23 or newer; a dongle on 1.20 is flashed once over USB).
- Downloads run over WiFi only, never over the ESPNetLink's mobile connection; the card still lists the updates and says why the buttons wait.
- The ESPNetLink's assisted GPS is switched on by the WiCAN PRO, and its access point when the dongle is used in WiFi mode.
- The firmware version reads `6.0.0-beta.2`; the build identifier moved to the About page and `/api/info`.
- J2534: ISO15765 messages follow the SAE J2534-1 layout (the 4-byte CAN id first, the pad flag per message), one ISO-TP session per flow-control filter, the TxDone and start-of-message indications. Standard tools and udsoncan work unchanged.
- J2534: J1850 VPW (GM Class 2) through the OBD chip, request and response. PWM and K-line stay unsupported.
- J2534 Windows driver 1.3.0: event-driven acknowledgements, a debug log, J1850 VPW.

## Bug fixes since alfa-06
- Fixed a full-scale reading dropped by its own range: a full tank (41 2F FF) decoded to 100.000001646 against a maximum of 100 and the value was discarded. Standard PID rows now clamp to the table's range, as the 4.x firmware did; a custom row's bounds stay a filter (#1004)
- Fixed a custom row's init leaking into the standard rows: a chain that moves the chip to a gateway behind extended addressing (ATSH6F1, ATCEA60, ATCRA660) froze every Mode 01 value that followed. The baseline is put back between row types, and Test a PID shows the restoring prelude (#964)
- Fixed J2534 testers timing out on every ISO15765 request because the device expected the bare payload instead of the J2534-1 layout
- Fixed the J2534 server unsubscribing another component's CAN queue before its first CONNECT

## New features in v6
- New UI design
- Added Quick Setup
- Improved AutoPID
- Improved CAN logger (raw CAN, SQLITE, Binary, Json)
- Improved Dashboard
- Improved CAN monitor
- Added support for Tailscale VPN
- Added support for USB devices (ESPNetlink, GPS, USB to Ethernet adapter)
- Added DTC Trouble codes
- Added DBC signals support
- Added New Rules and Events
- Added Scripting feature
- Added UDS Tools
- Added J2534 support
- Added File Manager (Sd card and Internal flash)
- Added System logs UI
- Added System Monitor UI
- AutoPID and Quick Setup support ISO 27145 (WWH-OBD) vehicles, such as Euro VI Sprinters over 3.5 t that answer only 22F4xx on 29-bit CAN. Reported working on a UK Sprinter by @billybigpotatoes, protocol findings by @CzarofAK (#298).
- Added VPN split tunnel: route only the networks you choose through WireGuard (up to 8 routes, .conf import). Replaces the Allowed IP and Mask fields, existing values are migrated (#975)
- Added Pause VPN per WiFi network: the tunnel stays down on a marked network (e.g. home WiFi) and comes back when the device leaves it (#976)
- Added full configuration Backup and Restore (settings, vehicle profiles and PIDs, code databases, DBC files, scripts, dashboard layout), with optional removal of sensitive data and optional encryption, plus backup copies kept on the internal flash and SD card (#979)
- ESPNetLink made easier: USB data mode (RNDIS) is the default, the header shows the USB device and its LTE/GPS state, a notice appears when a new dongle is plugged in, a dedicated ESPNetLink page, SIM PIN entry (locked and wrong PIN reported), a hint when the GPS gets no fix, and a Quick Setup path with no home WiFi that uses the dongle's LTE
- ESPNetLink: a console-only dongle is detected and reported, and the USB port power is cycled once when a dongle never enumerates
- Logger clock history: every clock step is journaled on the SD card (clock.jsonl), queued records are re-based, files rotate on large steps, and the History chart and the log file list show the clock context (#984)
- ABRP: deliveries are paced (5 s minimum period, 2.5 s minimum gap, backoff on HTTP 429), a coverage view shows which ABRP fields your vehicle provides, and error messages carry ABRP's own text
- Backup copies on the device carry a checksum per part, verified at boot and before a restore; a copy that predates a factory reset is held until you restore or refresh it; files left out of a backup are listed with a reason
- Connections: a socket server that no connection uses (e.g. slcan over TCP on port 3333) is flagged on the Connections card with a one-click CAN bus row, and All Settings shows which connection each server carries
- Reduced internal RAM use: long-lived state moved to PSRAM, about 10 KB freed

## Bug fixes in v6
- Fixed setting persist issue when upgrading from v4.51 to v6.00
- Fixed USB GPS not reporting until "Dongle console" was enabled. GPS is now read by default with its own switch (#978)
- Fixed "Download Config" backup not including AutoPID PIDs or vehicle profiles, replaced by the new Backup and Restore (#979)
- Fixed writing over an existing file on the SD card failing
- Fixed File Manager reporting the wrong capacity for SD cards over 4 GB (a 32 GB card showed as 976 MB) (#982)
- Fixed console commands that fail with an internal error printing nothing (#980)
- Added the station IP to the Home Assistant webhook payload for push-based installs (#977)
- Fixed Home Assistant "changed only" push sending a second full payload after registration
- Fixed SD logger timestamps shifting by one or two hours depending on whether the time server answered at boot (#984)
- Fixed a crash when an ESPNetLink or USB Ethernet adapter disconnected during a USB power repair cycle
- Fixed the Home Assistant webhook vpn_status reading past its table while the VPN was connected; vpn_status now uses the same words as the VPN page (#985)
- Fixed an encrypted backup made with "Remove sensitive data" restoring blank secrets (#986)
- Fixed the automatic backup copy losing its settings 20 s after a factory reset (#987)
- Fixed the VPN settings migration routing the Allowed IPs network instead of the tunnel subnet (#988). If you upgraded to Alfa-04 with the old Allowed IP and Mask fields set, check the Routes list once: the corrected migration runs only on devices still carrying the old fields
- Fixed a backup silently leaving out some files, and one large file failing the whole download (#989)
- Fixed slcan over TCP connecting but receiving nothing when the socket server had no CAN bus connection row: the device now logs a warning and the UI offers the row
- Fixed J2534 "communication established but no comm with the bus" with Automatic bit rate on a bus that only answers when asked: the tester's bit rate (J2534 connect or slcan S command) is adopted, and refused transmits are logged and counted
- Fixed the USB device mode (WiCAN as a network adapter to a PC) leaving a stale USB transfer across a restart; the PC now sees an unplug before the device comes back

## Known issues
- The ESPNetLink cannot update itself yet; it updates through a WiCAN PRO. A dongle on firmware 1.20 or older must be flashed once over USB.
- J2534: J1850 PWM and K-line are not supported; J1850 VPW is request and response only, no 4x speed.
- A firmware upload started within ten minutes of an update may show that update as "not yet verified" on the Updates card until the ten-minute mark, although it was confirmed.
